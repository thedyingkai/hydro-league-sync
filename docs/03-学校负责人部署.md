# 学校负责人部署指南

本文只处理学校侧 `hydro-league-agent`。中心 Hub、全局名单和密钥由联赛赛事方管理；学校负责人不需要部署 Hub，也不应取得中心管理员令牌。

## 1. 收到的文件

赛事方应单独提供：

- GitHub Release 中的 `hydro-league-agent-0.1.1.tgz` 和 `install-beta9.sh`。
- 同一 Release 的 `SHA256SUMS.txt`，用于核对公开交付物。
- 只属于本校的 `<site-id>.json`，包含站点 HMAC 密钥和本地比赛映射。该文件不得转发或提交到 Git。

公开发布页：<https://github.com/thedyingkai/hydro-league-sync/releases/tag/v0.1.1>

## 2. 上线前检查

插件严格面向 `hydrooj@5.0.0-beta.9`、root 所有的默认 Hydro 数据目录和 PM2 进程。安装脚本会再次核对版本。上线前必须完成：

- 备份 Hydro MongoDB、`/root/.hydro/addon.json`、`/root/.hydro/addons` 和 PM2 配置。
- 确认 Hydro 服务器可以通过 HTTPS 访问赛事方给出的 Hub 地址，并且系统时间已通过 NTP 校准。
- 选择无提交写入的维护窗口；不要在比赛进行中升级 Hydro 或替换插件。
- 核对本校 JSON 中的域 ID、24 位比赛 ObjectId、Hydro UID 和本地 PID。

Release 文件下载到学校服务器后执行：

```bash
sha256sum -c SHA256SUMS.txt --ignore-missing
```

只有 `hydro-league-agent-0.1.1.tgz: OK` 和 `install-beta9.sh: OK` 时才继续。

## 3. 标准安装

默认布局直接执行：

```bash
sudo -i
bash ./install-beta9.sh "$(realpath ./hydro-league-agent-0.1.1.tgz)"
```

自定义 Hydro 数据目录、PM2 进程名或健康页时使用环境变量：

```bash
HYDRO_HOME=/root/.hydro \
HYDRO_PM2_PROCESS=hydrooj \
HYDRO_HEALTH_URL=http://127.0.0.1:8888/ \
bash ./install-beta9.sh "$(realpath ./hydro-league-agent-0.1.1.tgz)"
```

脚本会先核对内置的官方包 SHA-256，把旧 Addon 和 `addon.json` 保存到 `/root/.hydro/backups/hydro-league-agent-<UTC时间>/`，使用包内锁定的纯 JavaScript 运行依赖，确认包内没有第二套 Hydro 或 React，登记 Addon，重启 PM2 并检查健康页。安装过程不访问 npm registry。任一步失败都会自动恢复安装前 Addon 状态。脚本不修改已有插件配置。自行从源码重建包时，必须用 `HYDRO_LEAGUE_AGENT_SHA256=<自建包哈希>` 明确覆盖官方哈希。

非 root、非 PM2 或自定义 Addon 布局不适用该脚本。此类服务器应先在同构测试实例中按现有 Hydro 运维方式完成登记，再安排生产变更。

## 4. 填写插件配置

在现有 Hydro 的插件配置入口中找到 `hydro-league-agent`，逐字段填入赛事方发放的本校 JSON。不要把整个 JSON 写入公开日志或聊天记录。结构示例仅用于识别字段：

```yaml
enabled: true
centerUrl: https://hub.example.edu
allowInsecureHttp: false
leagueId: league-2026
siteId: school-a
sharedSecret: <本校独立密钥>
contests:
  - domainId: contest-domain
    contestId: 0123456789abcdef01234567
    teamMapping:
      "1001": TEAM-001
    problemMapping:
      "1": problem-a
```

正式联调必须使用 HTTPS，并保持 `allowInsecureHttp: false`。只有 Hub 与 Hydro 在同一台机器上做隔离测试时才使用 `http://127.0.0.1:3000`。

保存配置后重启 Hydro：

```bash
pm2 restart hydrooj --update-env
pm2 logs hydrooj --lines 200
```

日志应出现 `Hydro League Agent enabled for site ...`，且不应持续出现鉴权、TLS、映射或版本错误。

## 5. 联调验收

先检查本机页面和 AGPL 对应源码：

```bash
curl -f http://127.0.0.1:8888/ >/dev/null
curl -f http://127.0.0.1:8888/hydro-league-agent-source.zip >/dev/null
```

再由赛事方确认中心状态中的本校为 `ONLINE`，`pending_events=0`、`rejected_events=0`。使用专门的测试账号完成 CE、WA、AC 各一次，核对 CE 不计罚次、WA 计一次罚时、AC 时间和本地比赛一致。

比赛的三个联赛视图应全部可访问：

```text
/d/<domain-id>/contest/<contest-id>/scoreboard/leagueboard
/d/<domain-id>/contest/<contest-id>/scoreboard/league-xcpcio
/d/<domain-id>/contest/<contest-id>/scoreboard/league-realboard
```

普通账号只能看到 public 数据，比赛拥有者或隐藏榜权限账号才可看到 jury 数据。原有本地榜、`realboard` 和 `xcpcio` 路由必须保持可用。

最后做一次短时断网测试：断网期间提交应留在本机 `league.sync.outbox`，恢复后自动补传并回到 `pending_events=0`。不得手工清空 outbox；出现 rejected 事件时保留现场并联系赛事方。

## 6. 回退

安装阶段失败时脚本已经自动回退。启用配置后才暴露的问题，先在 Hydro 插件配置中关闭 `enabled` 并重启 PM2；随后按安装输出中的备份目录和本校既有恢复流程恢复 Addon。恢复前保留日志、`addon.json` 备份和 MongoDB 中的 `league.sync.*` 集合，避免丢失尚未上报的提交。
