# Hydro 多校联赛同步方案（已确认设计）

## 1. 结论

原始思路可行，但中心端必须合并“提交与判定”，不能合并各校已经算好的名次。

建议拆成三个运行组件：

1. 学校端 `hydro-league-agent`：采集本校比赛终态判定，可靠上报；缓存并展示中心榜。
2. 中心端 `league-hub`：接收事件、幂等存储、统一计分、监控学校在线状态。
3. 展示与导出适配层：分别输出 XCPCIO Board、联赛 Realboard 数据和 ICPC Contest Data Package。

这样每所学校可以继续隔绝选手机房外网，同时由可联网的 Hydro 服务器完成上报和榜单缓存。

## 2. 已确认规则

- 赛制：ACM/ICPC。
- 编译错误（CE）不计罚时。
- 正式队伍参与排名；打星队伍展示成绩但不占正式名次。
- 学校断联后继续发布当前榜单，不隐藏、不删除该校数据。
- 公共榜必须标注断联学校、最后成功同步时间和“榜单可能不完整”的提示。
- 目标滚榜工具：ICPC Tools Resolver。
- 全局学校、队伍、题目和本地 Hydro 账号映射由统一 Excel 收集。

## 3. 中心计分原则

- 中心以 `site_id + domain_id + contest_id + rid` 唯一标识一条本地提交。
- 重判保持同一 `rid`，中心用更大的 `source_seq` 覆盖当前判定，不重复增加提交次数。
- AC 计解题数；WA、TLE、MLE、OLE、RE 等在首次 AC 前计错误罚时。
- CE、SE、FE、IGN 以及评测过程状态不计错误提交罚时。
- 首次 AC 后的后续提交不再影响该题得分和罚时。
- 公开榜在封榜后只展示冻结状态；裁判私榜继续计算完整结果。
- 提交时间以本地记录时间为准，因此所有学校服务器必须在赛前通过 NTP 校时。

## 4. 学校端采集与可靠性

Hydro `5.0.0-beta.9` 上应监听 `record/judge` 获取当前生效的最终评测结果，不以 `record/change` 作为正式结果来源。

`record/change` 会在创建、评测中间状态、最终状态和重判 reset 时多次触发；它适合 Realboard 动画，不适合作为唯一的可靠上报依据。

学校端处理流程：

1. `record/judge` 回调只做快速、本地、幂等的 outbox 写入。
2. 后台任务按 `source_seq` 批量上报，收到中心 ACK 后再确认本地事件。
3. 网络失败时指数退避，事件不丢弃、不跳号。
4. 插件启动、固定周期和比赛结束时扫描本地比赛终态记录做 reconciliation。
5. 上报只包含榜单必需字段，不发送代码、测试点、编译器输出或账号密码。

建议事件字段：

```text
protocol_version, league_id, site_id, source_seq,
domain_id, contest_id, rid, uid, pid,
status, score, lang, submitted_at, judged_at, rejudged,
global_team_id, global_problem_id, emitted_at
```

中心批量接口必须支持重复、乱序和重放。每个站点使用独立凭证；请求带时间戳、随机数和 HMAC 签名，中心验证重放窗口。

## 5. 榜单与滚榜出口

### 5.1 完整联赛榜

中心从规范化提交表重新计算榜单，并输出 XCPCIO all-in-one 数据结构。学校端 Hydro 插件从中心拉取后落入本地缓存，再由选手机通过本校 Hydro 页面查看。

学校端页面不直接让浏览器访问公网，以免破坏机房隔离策略。

建议保留 Hydro 原有本地榜，新增 `leagueboard` 视图。联赛服务故障时，管理员仍可对照本地榜排查。

### 5.2 联赛 Realboard

当前服务器上的 Realboard 是“最近提交的等待/最终结果动画”，不是完整总榜，也不是可靠同步组件。它的初始快照读取本机 `ContestModel`，增量读取本机 `record/change`。

实现直接 fork 其 `ResolverInput`、模板、CSS、React 组件、React Spring 动画和双阶段队列，新增 `league-realboard`：

- 初始状态与后续修订都来自经学校 Hydro 权限隔离、严格校验并缓存的 XCPCIO all-in-one 数据。
- 同一 `submission_id` 从 pending/frozen 到最终 verdict 的修订触发上游队列动画；断线重传进入快照后也不会漏掉最终状态。
- 本地 Hydro 只做代理和缓存。
- 保留现有 `realboard` 名称，避免注册冲突并保留赛时降级通道。

### 5.3 ICPC Tools Resolver / CDP

全局 CDP 必须由中心数据库一次性生成，不能把多校 CDP 压缩包直接拼接。

输出遵循 ICPC Contest API `2023-06`，包含闭合引用的 contest、state、judgement-types、languages、groups、organizations、teams、problems、submissions 和 judgements 事件。

现有 `onsite-toolkit 0.1.0-beta.2` 只能作为代码参考，不能原样使用，至少需要修正：

- `scoreboard_freeze_duration` 应为 `endAt - lockAt`，不是 `lockAt - beginAt`。
- 不能伪造 `judgeTime = submitTime + 1 秒`。
- contest/state 单例通知和事件 ID 必须符合规范。
- 必须从中心当前生效的重判结果生成，并做 Schema 校验和 Resolver 实际回放。

## 6. 断联状态

中心按最近 ACK/心跳时间计算站点状态：

- `ONLINE`：同步延迟在正常阈值内。
- `DELAYED`：超过预警阈值，但尚未判定断联。
- `OFFLINE`：超过断联阈值。

公共榜继续使用已收到的数据，并显示：

```text
第二学校已断开连接，最后同步于 10:42:18；当前名次可能不完整。
```

恢复连接后学校端自动补传，中心重新计算并更新榜单；不手工清空该校历史数据。

## 7. 学校服务器部署边界

每所学校的 Hydro 都是生产测评机，不能兼任中心 Hub，也不能直接拿正式比赛数据做开发测试。上线前应在同版本隔离实例完成安装、断网补传和回滚演练，再安排停写窗口进入生产机。

- 当前严格兼容目标是 `hydrooj@5.0.0-beta.9` 和 Node.js 22。
- 学校服务器必须通过 NTP 校时，并能从服务器网段出站访问中心 HTTPS；选手机房无需公网路由。
- 安装前备份 MongoDB、`addon.json`、Addon 目录和进程管理配置。
- 新插件只新增 `leagueboard`、`league-xcpcio` 和 `league-realboard`，不得覆盖原有本地榜或 `realboard`。
- 不得在配置文件中保存中心管理员令牌；学校只持有本站 HMAC 密钥。
- 正式凭据不得写入仓库、日志、命令历史、工单或截图，应由权限受控的密钥文件或配置系统管理。

仓库中的 Realboard 上游快照来自公开版本，用于许可证溯源、可重复构建和二次开发；它不代表任何学校生产服务器上的私有修改。

## 8. 复用和许可证边界

- Realboard 展示代码可以改造，但二次开发版本需继续遵守 AGPL-3.0，并保留 NOTICE。
- Hydro `scoreboard-xcpcio` 的包装层为 AGPL；`@xcpcio/board-app` 源码主体为 MIT，但官方预编译包会静态带入 Highcharts。交付版从固定上游提交重构建只保留 Board 路由，删除 Rating/Statistics 及 Highcharts/Highstock/GSAP 依赖，不直接分发该官方预编译包。
- `xcpc-tools` 为 AGPL，可继续用于现场气球、打印等运维，不作为联赛聚合器。
- 中心协议和新业务代码建议同样公开源代码，减少许可证组合风险。

## 9. 建议接口

```text
POST /api/v1/sites/{site_id}/events:batch
POST /api/v1/sites/{site_id}/snapshot
GET  /api/v1/leagues/{league_id}/scoreboard?view=public|jury
GET  /api/v1/leagues/{league_id}/submissions?cursor=...
GET  /api/v1/leagues/{league_id}/sites/status
POST /api/v1/leagues/{league_id}/finalize
GET  /api/v1/leagues/{league_id}/cdp.zip
POST /api/v1/leagues/{league_id}/publish-results
```

## 10. 实施顺序

1. 锁定协议、目标 Hydro 版本和 Excel 导入规则。
2. 实现中心数据模型、幂等接收、计分和站点状态。
3. 实现学校端 outbox、上报、补偿扫描和健康检查。
4. 实现 Hydro `leagueboard` 页面及本地缓存。
5. 适配 `league-realboard`、XCPCIO Board 和 CDP。
6. 用三所模拟学校验证断网、乱序、重复、重判、封榜和恢复补传。
7. 先做一场影子联调，再进入正式比赛。

## 11. 已确认开发边界

1. 学校生产测评机禁止作为中心部署或开发测试目标。
2. 本地开发中心只绑定 `127.0.0.1`；正式中心使用独立服务器和 HTTPS 反向代理。
3. 首个兼容目标为 Hydro `5.0.0-beta.9`，其他版本通过 Excel 收集后建立兼容矩阵。
4. 可以 fork Realboard 的适用代码；可靠同步、中心计分和 CDP 仍作为独立组件实现。
5. 裁判私榜默认仅比赛管理员可访问；普通选手只访问公开冻结榜。
6. 接受 AGPL，并保留上游版权、许可证和 NOTICE。
