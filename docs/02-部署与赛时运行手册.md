# Hydro 多校联赛部署与赛时运行手册

本文面向赛事管理员。Windows PowerShell 示例假设仓库位于 `C:\hydro-league-sync`，本地中心地址为 `http://127.0.0.1:3000`；使用其他路径时按实际仓库根目录替换。

## 1. 安全边界

学校 Hydro 是生产测评机，不是中心服务器或开发环境。中心安装、配置导入、Docker 和破坏性测试只能在独立中心机或隔离实例执行；学校端插件应先在同版本测试实例验证，再按停写窗口上线，不得把学校生产机临时改作中心。

本机测试只绑定 `127.0.0.1`。正式中心示例使用 `https://hub.example.edu`；Hub 仍只监听宿主机 `127.0.0.1:3000`，公网只开放反向代理的 HTTPS，不得把裸露的 Hub 端口直接开放到公网。

## 2. 架构与数据流

每所学校保留独立 Hydro 和本地比赛，机房选手网络可以完全隔离外网。能访问外网的 Hydro 服务器安装 `hydro-league-agent`：

1. 插件从 Hydro `record/judge` 捕获最终评测结果，先持久化到本机 MongoDB outbox，再进行网络请求。
2. 插件用站点独立 HMAC 密钥批量上报。失败时指数退避，收到中心明确 ACK 后才确认本地事件；周期 reconciliation 修复遗漏或重启造成的不一致。
3. `league-hub` 把事件幂等写入 SQLite，以 Excel 导入的全局队伍和题目映射为权威，重新计算联赛榜。中心不合并各校已计算的名次。
4. Hub 分别提供 public 封榜数据、jury 实时数据、XCPCIO JSON、cursor 提交流、Contest API 和赛后 CDP。
5. 学校端插件从 Hub 拉取数据并保存在 public/jury 隔离缓存中，再通过本校 Hydro 同源页面提供给用户。选手浏览器不直接访问公网中心。

上报只包含榜单所需元数据，不包含代码、测试数据、编译输出、运行输入输出或账号密码。未映射事件保留在中心 quarantine，但不会进入正式榜。

## 3. 运行前提

- Node.js `22.5` 或更新版本；开发和测试使用 npm。
- Docker 方式需要 Docker Desktop/Engine 和 Compose v2。
- 所有 Hydro 服务器、中心服务器和滚榜机必须通过 NTP 校时，时区统一为 `Asia/Shanghai`。提交时间用于罚时和封榜，HMAC 请求也有时间戳窗口。
- 正式中心需要可验证的 TLS 证书、反向代理、受限管理来源和稳定磁盘。
- 每所学校使用独立的至少 32 UTF-8 字节 HMAC 密钥；管理员令牌也至少 32 字节。

首次安装依赖并验证：

```powershell
Set-Location C:\hydro-league-sync
node --version
npm ci
npm run build
npm run typecheck
npm test
```

## 4. Excel 收集与配置生成

赛事信息模板位于：

`C:\hydro-league-sync\templates\league-participant-template.xlsx`

收齐并复核联赛、学校、全局队伍到本地 Hydro UID、全局题目到本地 PID 的映射后执行：

```powershell
Set-Location C:\hydro-league-sync
npm run import:config -- <xlsx> [private-dir] [center-url]
```

例如，本机联调可使用：

```powershell
$Workbook = 'C:\contest-private\source\league-participants.xlsx'
$PrivateDir = 'C:\contest-private\league-2026'
npm run import:config -- $Workbook $PrivateDir http://127.0.0.1:3000
```

正式环境应把第三个参数设为赛事中心 HTTPS 地址，例如 `https://hub.example.edu`，然后重新生成全部学校配置。导入器默认直接拒绝非回环 HTTP；只有受控内网临时联调才可显式追加 `--allow-insecure-http`，正式环境禁止使用该开关。

导入器校验 Hydro `5.0.0-beta.9`、ACM/ICPC、CE 不罚时、ObjectId、唯一 ID、完整题目映射、题包/Checker 哈希、时间和断联阈值。失败时必须修正 Excel 后重跑，不能绕过校验。

输出目录包含：

| 文件 | 用途 |
| --- | --- |
| `hub-config.json` | Hub 全量配置；包含站点密钥、比赛、学校、队伍、题目和权威映射 |
| `site-secrets.json` | 管理员令牌与每站 HMAC 密钥的主备份 |
| `.env.hub` | Hub 本机环境变量，包括管理员令牌和断联时限 |
| `site-configs/<site-id>.json` | 分发给对应学校的插件配置；包含该校密钥与本地映射 |
| `import-report.json` | 导入计数、中心地址和待处理警告，不作为运行配置 |

填妥的 Excel 含联系人、学号和账号映射，也应放进受控的 `private-config` 或仓库外私密目录，不要覆盖公开空模板。同一输出目录再次导入会复用现有密钥，避免无意中让全部学校掉线。整个 `private-config` 是私密材料：限制 ACL、加密备份，不提交 Git，不放到群文件或公开网盘，不在工单和截图中展示。每所学校只能拿到自己的 `site-configs/<site-id>.json`，不能拿到 `hub-config.json` 或 `site-secrets.json`。

## 5. 用 Node 在本机启动 Hub

先生成配置。随后在用于运行 Hub 的 PowerShell 会话加载环境变量并指定数据库：

```powershell
Set-Location C:\hydro-league-sync
$PrivateDir = 'C:\contest-private\league-2026'

Get-Content "$PrivateDir\.env.hub" | ForEach-Object {
  if ($_ -match '^([^#=]+)=(.*)$') {
    Set-Item -Path "Env:$($Matches[1])" -Value $Matches[2]
  }
}
$env:HYDRO_LEAGUE_DATABASE = 'C:\hydro-league-sync\data\league-hub.sqlite'

npm run build
npm run start:hub
```

该进程应输出监听 `http://127.0.0.1:3000`。配置导入前 `/healthz` 可返回 `configured=false`，而 `/readyz` 返回 503，这是预期状态。保持该终端运行，在另一个 PowerShell 窗口执行第 7 节的配置 PUT。

开发时可用 `npm run dev:hub` 自动重载；正式运行应使用进程管理器调用 `npm run start:hub`，设置自动重启、日志轮换和服务账号。

## 6. 用 Docker 在本机启动 Hub

Compose 只把宿主端口映射到 `127.0.0.1:3000`，数据库保存在命名卷 `league-hub-data`：

```powershell
Set-Location C:\hydro-league-sync
$PrivateDir = 'C:\contest-private\league-2026'

docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml up --build -d
docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml ps
Invoke-RestMethod http://127.0.0.1:3000/healthz
```

查看日志和停止服务：

```powershell
docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml logs -f league-hub
docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml down
```

普通 `down` 保留数据库卷；不要在没有确认备份的情况下使用 `down -v`。启动后仍须执行配置 PUT。

## 7. 向 Hub 导入全量配置

`PUT /api/v1/admin/config` 是全量替换，不是增量合并。新配置遗漏的旧站点会被禁用并清除其中心密钥，因此必须始终使用本次完整 Excel 生成的原始 `hub-config.json`。管理员 `GET` 返回的是脱敏配置，不能把脱敏结果直接当作下一次 PUT 的源文件。

```powershell
$PrivateDir = 'C:\contest-private\league-2026'
$Secrets = Get-Content -Raw "$PrivateDir\site-secrets.json" | ConvertFrom-Json
$Headers = @{ Authorization = "Bearer $($Secrets.admin_token)" }

Invoke-RestMethod `
  -Method Put `
  -Uri 'http://127.0.0.1:3000/api/v1/admin/config' `
  -Headers $Headers `
  -ContentType 'application/json' `
  -InFile "$PrivateDir\hub-config.json"

Invoke-RestMethod http://127.0.0.1:3000/readyz
Invoke-RestMethod `
  -Uri 'http://127.0.0.1:3000/api/v1/admin/config' `
  -Headers $Headers
```

成功响应包含 `ok=true`；随后 `/readyz` 必须返回 `ready`。不要把 `$Secrets` 或请求头输出到日志。

公开 Nginx 示例直接拒绝 `/api/v1/admin/*`、`finalize` 和 `publish-results`。正式导入、结算和发布必须先建立 SSH 本地转发，再把本节命令中的 Hub 地址改为转发端口：

```powershell
ssh -N -L 3300:127.0.0.1:3000 hub-admin@HUB_SSH_HOST
```

保持该会话运行，在另一个终端访问 `http://127.0.0.1:3300`。站点 HMAC 上报、公开榜单、受 Basic/Bearer 保护的 jury/Contest API、CDP 和 AGPL 源码仍走正式 HTTPS 域名。

## 8. 每校 Hydro beta9 插件安装与配置

兼容目标严格固定为 `hydrooj@5.0.0-beta.9`。在每所学校现有 beta9 宿主中，使用该版本已有的 addon 安装/登记机制注册 `hydro-league-agent` 交付目录；包根必须保留 `index.js`。不同 Hydro 部署方式的 addon 管理命令并不统一，本文不臆造命令。实际包结构、配置 schema 和兼容依据以 [`packages/hydro-league-agent/README.md`](../packages/hydro-league-agent/README.md) 与 [`HYDRO-5.0.0-beta.9.md`](../packages/hydro-league-agent/docs/HYDRO-5.0.0-beta.9.md) 为准。

给每校管理员单独分发 `site-configs/<site-id>.json`，将其中字段完整填入该插件的配置作用域。典型结构如下，实际值必须来自导入器：

```yaml
enabled: true
centerUrl: https://hub.example.edu
allowInsecureHttp: false
leagueId: league-2026
siteId: school-a
sharedSecret: <该校独立密钥>
contests:
  - domainId: system
    contestId: 0123456789abcdef01234567
    teamMapping:
      "1001": TEAM-001
    problemMapping:
      "1": A
```

本机一体化联调才使用 `centerUrl: http://127.0.0.1:3000`。学校服务器访问正式中心时必须使用 HTTPS，且 `allowInsecureHttp: false`。不要把密钥写进 URL、聊天记录或公开日志。

插件启动日志应出现 `Hydro League Agent enabled`。随后检查 Hub `/api/v1/leagues/<league-id>/sites/status`，确认学校从 `OFFLINE` 进入 `ONLINE`；再做一条测试提交并核对 Hub 榜单。缺失映射必须在赛前修正 Excel 并重新全量 PUT，不能只在插件端伪造全局 ID。

## 9. 学校端联赛视图与权限

三个视图都挂在对应 Hydro 比赛的 scoreboard 视图下：

- `leagueboard`：正式主入口；学校 Hydro 服务端按权限代理 XCPCIO all-in-one JSON，交给仓库中固定版本、二次开发的自托管 XCPCIO Board scoreboard-only fork。
- `league-xcpcio`：与 `leagueboard` 完全相同的 XCPCIO 兼容别名，不维护第二套榜单实现。
- `league-realboard`：直接复用 HandsomeRun Hydro Realboard fork 的 React/React Spring 动画、排名和双阶段队列；输入改为同一份权限隔离后的 XCPCIO all-in-one 联赛数据。

它们使用独立名称，不注册或覆盖现有 `realboard`、`xcpcio`，本地比赛榜仍可作为故障排查参照。对应路径形式为：

```text
/d/<domain-id>/contest/<contest-object-id>/scoreboard/leagueboard
/d/<domain-id>/contest/<contest-object-id>/scoreboard/league-xcpcio
/d/<domain-id>/contest/<contest-object-id>/scoreboard/league-realboard
```

Hydro 本地比赛拥有者，或拥有隐藏榜权限 `PERM_VIEW_CONTEST_HIDDEN_SCOREBOARD` 的用户，得到 jury 实时视图；其他用户只得到 public 视图。权限判断在学校 Hydro 服务端完成，public/jury 缓存严格分离。不要把中心管理员 Bearer 发给学校管理员或浏览器。

Hub 根页面直接加载同一份 XCPCIO fork，固定使用匿名 public 数据源 `/api/v1/scoreboard/xcpcio.json`；该固定入口不接受 query，不能用 `view=jury` 绕过封榜。Hub 的受限 `view=jury`、Contest API、event-feed 和 CDP 需要中心管理员 Bearer、正确的站点 HMAC，或仅供中央 ICPC Tools 使用的 HTTP Basic：用户名固定为 `jury`，密码为中心管理员令牌。学校端继续使用各自的站点 HMAC，不得保存中心管理员令牌；管理配置、quarantine 和 mapping audit 只接受管理员 Bearer。正式公网部署必须在 HTTPS 后使用 Basic，禁止明文跨网传输凭据。

## 10. 计分、打星与封榜

- ACM/ICPC：按解题数降序、总用时升序排序，同成绩共享名次。
- `COMPILE_ERROR`/CE、系统错误、格式错误、忽略和取消不计错误罚次；WA、TLE、MLE、OLE、RE 等在首次 AC 前按配置罚时。
- 首次 AC 后的提交不再改变该题得分；重判以同一提交 ID 的最新结果覆盖，不重复计算提交。
- 正式队伍参加排名；Hub、Hydro 联赛榜和 XCPCIO 视图中，打星队伍显示成绩但 `rank` 为 `null`，不占正式名次。ICPC Contest API 要求 `scoreboard.rows[].rank` 为正整数，因此 CDP 的主榜先列全部正式队并保留正式名次，再把打星队列在正式队之后；打星队在 CDP 中的后续整数仅用于满足交换格式和保留可见性，不代表正式名次。
- public 在 `freeze_time` 后隐藏新的判定，jury 始终显示实时结果。导入器默认写入 `unfreeze_at: null`，因此公开榜会持续冻结，直到管理员明确解封。

解封前先备份并确认所有学校已补传、quarantine 为零、mapping audit 已处理。赛事封存和 Resolver 滚榜完成后，使用第 12 节的 `publish-results` 管理接口发布最终榜。该动作独立于数据封存并且幂等，不需要也不允许再修改已经封存的全量配置。不要只为解封临时删除 `freeze_time`，也不要在名单不完整时发布最终名次。

## 11. 赛时监控与断联响应

公开监控：

```powershell
$LeagueId = 'league-2026'
Invoke-RestMethod "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/sites/status"
Invoke-RestMethod "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/scoreboard?view=public"
```

管理员排查映射：

```powershell
Invoke-RestMethod 'http://127.0.0.1:3000/api/v1/admin/quarantine' -Headers $Headers
Invoke-RestMethod 'http://127.0.0.1:3000/api/v1/admin/mapping-audit' -Headers $Headers
```

站点状态按最近 ACK/心跳分为 `ONLINE`、`DELAYED` 和 `OFFLINE`。心跳同时上报本地待发送和拒绝事件数；即使网络状态是 `ONLINE`，任一计数非零也会把 `accuracy.complete` 置为 false 并阻止默认封存。任一学校断联、延迟或存在同步积压时：

1. 继续发布当前榜，不删站点、不清历史提交，并对外保留“该校断开/延迟，当前名次可能不完整”和最后同步时间。
2. 联系该校检查 Hydro 进程、插件日志、到正式中心的 DNS/TLS/出口、NTP 和防火墙；不要让选手机房临时开放公网。
3. 不要为消除告警重导入一个缺少该校的配置。全量配置遗漏站点会禁用该站点密钥。
4. 网络恢复后让本地 outbox 自动补传，等待 reconciliation 完成；确认站点变为 `ONLINE`、未映射数为零、榜单 cursor 前进。
5. 补传完成前发布的名次一律标注“可能不完整”。只有所有站点恢复且审核通过后，才能宣布最终名次和解封。

若插件日志出现 `League event delivery failed` 或 `League heartbeat failed`，事件仍在本地 outbox 等待重试；不要手工删除 MongoDB outbox。出现 rejected 事件必须保留现场并根据中心返回原因处理。

## 12. XCPCIO JSON 与 Resolver CDP

公开 XCPCIO all-in-one JSON 可匿名导出；下面的 jury 导出示例使用管理员 Bearer（也可按前述权限边界使用站点 HMAC 或中央 `jury` Basic）：

```powershell
$LeagueId = 'league-2026'
Invoke-WebRequest `
  -Uri "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/xcpcio.json?view=public" `
  -OutFile ".\$LeagueId-public-xcpcio.json"

Invoke-WebRequest `
  -Uri "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/xcpcio.json?view=jury" `
  -Headers $Headers `
  -OutFile ".\$LeagueId-jury-xcpcio.json"
```

CDP 只允许比赛结束并显式封存后导出；赛前、赛中或未封存时请求返回 HTTP 409。封存是有副作用的管理员 `POST`，下载 CDP 的 `GET` 保持只读。默认封存要求所有学校 `ONLINE`、本地待发送和拒绝事件均为零；先确认全部 outbox 补传、reconciliation 完成、quarantine 和 mapping audit 已处理，再执行：

```powershell
$LeagueId = 'league-2026'
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/finalize" `
  -Headers $Headers `
  -ContentType 'application/json' `
  -Body '{}'
```

封存成功会写入严格有序的 `thawed`、`finalized` 和最后一个 `end_of_updates` 事件，并立即拒绝后续提交、快照及配置 PUT。若仍有断联、延迟、同步积压或拒绝事件，接口返回 `sites_not_ready`，此时应恢复连接并补传。只有赛事负责人确认某校数据永久无法恢复并接受不完整最终名次时，才可显式传入 `{"force":true}`；响应会保留 `forced=true` 和不完整警告。

封存成功后只读导出 CDP：

```powershell
$ExportDir = 'C:\hydro-league-sync\exports\league-2026'
New-Item -ItemType Directory -Force -Path $ExportDir | Out-Null

Invoke-WebRequest `
  -Uri "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/cdp.zip" `
  -Headers $Headers `
  -OutFile "$ExportDir\$LeagueId-cdp.zip"

Expand-Archive `
  -LiteralPath "$ExportDir\$LeagueId-cdp.zip" `
  -DestinationPath "$ExportDir\cdp" `
  -Force
```

导出的 Contest Package 遵循 ICPC Contest API `2023-06`，根目录包含 `api.json`、`contest.json`/`contest.yaml`、各资源 JSON、`problems.yaml` 和 `event-feed.ndjson`。Hub 使用封存时的 jury 结果生成，赛后 state 标记 thawed/finalized/end_of_updates；不要拼接多校 CDP。误封存不能在原数据库中撤销，只能从封存前备份恢复到新的隔离实例，补齐数据并重新审核。

在滚榜机安装 ICPC Tools Resolver 发布包和 Java 17+，解压 Resolver 发布包后从其主目录运行。正式滚榜必须显式只选择 `official` 组：

```powershell
.\resolver.bat 'C:\hydro-league-sync\exports\league-2026\cdp' --groups '^official$'
```

Linux/macOS 对应：

```bash
./resolver.sh /path/to/league-2026/cdp --groups '^official$'
```

Resolver 的第一个参数可以是 Contest Package 目录。`groups.json` 中的 `type: eligibility` 只表示分组维度，Contest API 分组本身不会自动把 `unofficial` 队排除出总排名；真正的正式队过滤由上面的 `--groups '^official$'` 完成。CDP 仍保留打星队、提交和判定，若要单独检查打星队滚榜，可在非正式预演中改用 `--groups '^unofficial$'`，但不得把该回放当作正式结果。正式滚榜前用同一份 CDP 在备用机器完整回放一次，核对队名、学校、题号、正式队最终名次、封榜提交和奖项停顿；保留原始 ZIP 的 SHA-256 和只读备份。

滚榜及最终审核完成后，再发布 Hydro 公共最终榜：

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:3000/api/v1/leagues/$LeagueId/publish-results" `
  -Headers $Headers
```

返回 `frozen=false` 后，普通用户的 `leagueboard`、`league-xcpcio` 和 `league-realboard` 会取得最终结果。重复调用不会改变首次发布时间。

## 14. HTTPS、备份与密钥轮换

正式中心应让 Hub 继续监听本机回环地址，或让 Docker 只映射宿主回环端口，由同机反向代理终止 HTTPS。学校服务器只需出站访问中心 HTTPS，选手网段不需要公网路由。公网业务使用 443；采用 HTTP-01 自动续期时，80 只用于 ACME challenge 和 HTTPS 跳转。管理接口应额外限制来源。

仓库提供两份通用 Nginx 示例。部署前先把文件名、`server_name` 和证书目录中的 `hub.example.edu` 全部换成正式域名；`/var/www/acme`、`/var/log/nginx` 和 `/etc/letsencrypt` 是目标机通用路径，不要把真实证书或目标机配置提交回仓库。推荐顺序：

```bash
sudo install -d -o root -g root -m 0755 /var/www/acme
sudo cp deploy/nginx/hub.example.edu.acme.conf /etc/nginx/conf.d/hydro-league.conf
sudo nginx -t
sudo systemctl reload nginx

sudo certbot certonly --webroot -w /var/www/acme -d hub.example.edu
sudo cp deploy/nginx/hub.example.edu.conf /etc/nginx/conf.d/hydro-league.conf
sudo nginx -t
sudo systemctl reload nginx
sudo certbot renew --dry-run
```

执行前必须先让正式域名 DNS 指向反向代理主机并放行 80/443。上例中的域名应使用替换后的正式值。续期钩子必须在证书更新后执行 `nginx -t` 和 reload；切换 HTTPS 配置后，从外部网络复核 TLS 证书、`/healthz`、公开榜和被 Nginx 拒绝的管理路径。

数据库使用 SQLite WAL 模式。备份时不能只复制 `league-hub.sqlite`：已提交数据可能仍在 `league-hub.sqlite-wal` 中。Node 方式应先停止 Hub 进程，再把数据库所在的整个数据目录作为同一份备份复制，至少必须同时保存主库、`-wal` 和 `-shm`；恢复时也整组恢复。Docker 方式先停止服务，再从停止的容器复制整个 `/data`，随后恢复服务：

```powershell
$Stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$BackupDir = ".\backups\league-hub-data-$Stamp"
New-Item -ItemType Directory -Force -Path $BackupDir | Out-Null

docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml stop league-hub
docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml cp `
  league-hub:/data/. $BackupDir
docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml start league-hub
Invoke-RestMethod http://127.0.0.1:3000/readyz
Get-ChildItem -File $BackupDir | Get-FileHash -Algorithm SHA256
```

备份期间不要执行 `docker compose down -v`。同时加密备份原始 Excel、完整私密输出目录和部署版本源码。恢复演练必须在隔离的 `127.0.0.1` 实例完成，不能直接在学校生产测评机上进行。

当前实现不支持一个站点同时使用新旧两把密钥。常规轮换应在非比赛时段逐校进行：备份；通过组织密钥管理系统生成至少 32 字节的新随机密钥；同步更新 `site-secrets.json`、私密 `hub-config.json` 和该校 `site-configs/<site-id>.json`；先全量 PUT 中心，再立即更新并重启该校插件。短暂鉴权失败期间 outbox 会保留事件，恢复后自动补传。逐校确认 `ONLINE` 后再处理下一校。

管理员令牌来自 Hub 启动环境。轮换时同时更新 `site-secrets.json` 的 `admin_token` 和 `.env.hub` 的 `HYDRO_LEAGUE_ADMIN_TOKEN`，然后重启 Node 进程；Docker 使用更新后的 env 执行 `docker compose --env-file "$PrivateDir\.env.hub" -f .\compose.local.yml up -d --force-recreate league-hub`。比赛期间除非确认泄露，不做批量轮换；发生泄露时先隔离受影响凭证和来源，再按事件响应流程轮换并审计 mapping/quarantine。

## 15. 已知风险与 AGPL 源码
